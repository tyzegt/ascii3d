## 0. Выводы из анализа текущей архитектуры

Ключевые факты, которые определяют дизайн фич:

1. **Один символ = один «пиксель».** Разрешение ~`canvas/charW × canvas/charH`
   (обычно ~200×70). Растеризация идёт по ячейкам, поэтому per-cell операции дешёвые
   и допустимы (в отличие от пиксельного рендера).

2. **Глиф уже кодирует яркость.** `GlyphMap.RAMP` = `' .:-~*+#%@'` (от пустого к
   тёмному), `GlyphMap.byIntensity(intensity 0..1)` уже есть. Сейчас растеризатор
   использует константу `#` (`GlyphMap.polygon()`), а `utils/Colors.js` — только
   заготовка (один направленный свет, Ламберт + ambient, не подключён к рендеру).

3. **Цвет сейчас назначается по мешу**, а не по грани/пикселю: `FrameBuffer.ids`
   хранит `meshId`, `flush()` красит целые прогалины из `Config.MESH_PALETTE`
   (`palette[id]`). Для цветных источников света этого недостаточно — нужен
   per-cell цвет.

4. **Нормали граней есть, но в локальном пространстве.** `Mesh.faces[i].normal`
   считается в `computeNormals()` (CCW наружу) и трансформируется в camera-space
   для back-face culling (`Projection.normalToCamera`). Для освещения нужна
   **мировая** нормаль (взять 3×3 из `worldMatrix` и нормализовать; при
   неоднородном масштабе это приближение — приемлемо для ascii).

5. **Грани триангулированы** (куб = 12 треугольников, 6 групп граней).
   Вершины куба **общие между гранями**, поэтому UV нельзя вешать на вершину —
   только **на угол грани** (`faces[i].uv` длины 3, параллельно `indices`).

6. **Near-clip уже интерполирует вершины** (`clipNear`/`lerpVerts`). Чтобы
   перспективно-корректная текстура пережила клип, `CVertex` должен нести `u,v`
   и `lerpVerts` должен интерполировать их линейно в camera-space (это корректно:
   UV линейно меняется по плоской грани в 3D).

7. **Строгий порядок загрузки + `expected`-список** в `main.js:26` и `index.html`.
   Любой новый модуль обязан попасть в оба места (+ в списки `test/*_test.html`),
   иначе бут прервётся «missing modules».

8. **Сцены — JSON-подобные данные.** `SceneLoader.load` рекурсивно создаёт объекты
   по `type` из `A3D.SceneRegistry`; `Scene.toJSON()` даёт round-trip. Источники
   света и материалы должны пройти через этот же путь (парсинг + сериализация).

9. **Заготовка под освещение уже есть** (`utils/Colors.js`, `Config.GLYPH_MAP`,
   `GlyphMap.byIntensity`). Её можно развить, а не писать с нуля.

## 1. Общий дизайн

### 1.1 Освещение

- **Сцена несёт список источников света** `scene.lights` (плоские объекты-данные,
  без классов). Каждый свет:
  - `type`: `'point'` (омни / сфера) | `'directional'` (однонаправленный / конус).
  - `color`: `[r,g,b]` (0..1) — цвет света.
  - `intensity`: множитель (обычно 0..1, допустимо >1).
  - `position` (для point): `[x,y,z]` в мировых координатах.
  - `direction` (для directional): `[dx,dy,dz]` — вектор, куда светит.
  - (опц., будущее) `angle`/`range` для конического spotlight — в этом плане
    «однонаправленный конус» трактуется как параллельный направленный свет;
    конический falloff вынесен в опции этапа B.

- **Модель освещения** (на грань, flat-shading — стандарт для ascii):
  ```
  contribution_light = lightColor * intensity
                       * max(0, dot(normal, -lightDir))     # Ламберт
                       * attenuation                        # для point: 1/(1 + k*d^2)
  lightRGB = ambient*white + Σ contributions               # clamp 0..1
  ```
  - Для `point`: `lightDir = normalize(light.position - facePosition)`.
  - Для `directional`: `lightDir = light.direction` (нормализованный).
  - `ambient` — глобальный, из `Config.AMBIENT`.

- **Тёмная сцена без источников.** `Config.AMBIENT = 0.1` → `lightRGB ≈ 0.1`
  (затемнение ~90%). `GlyphMap.byIntensity(0.1)` → индекс `round(0.1*9)=1` → `'.'`
  — тускло, но видимо, не чёрный. Для текстурированных граней затемнение уходит
  в цвет (глиф текстуры, цвет = материал × свет).

- **Как свет влияет на вывод** (два режима):
  - **Без текстуры**: глиф = `GlyphMap.byIntensity(luminance)`, где
    `luminance = max(lightRGB)` (или `0.3r+0.59g+0.11b`); цвет = материал.
    → классический градиент символов по граням (видно освещённые/теневые стороны).
  - **С текстурой**: глиф = символ из текстуры; цвет = `материал × lightRGB`
    (per-cell). → текстура читается, свет затемняет/окрашивает её.

- **Цветной свет** требует per-cell цвета в буфере (см. 1.3).

### 1.2 Текстуры

- **Текстура = набор ascii-символов** (плоский массив `w*h`), плюс ширина/высота:
  ```js
  // js/render/Texture.js
  A3D.modules.Texture = {
    registry: { 'brick': {...}, 'window': {...}, ... },   // именованные текстуры
    define(name, w, h, glyphs /* "...." | [..] */) -> void,
    get(name) -> texture,
    sample(texture, u, v) -> char,                        // u,v в [0,1] -> символ
    uvForFaceGroup(type, group) -> uv[3]                  // хелпер для примитивов
  };
  ```
  Текстуру можно задать **по имени** (из реестра) или **инлайн-сеткой** прямо в сцене.

- **Привязка к граням.** Две формы в JSON объекта:
  - `"texture": "brick"` — ко всем граням.
  - `"textures": { "front": "window", "top": "roof", ... }` — к именованным
    **группам граней** (разные текстуры разным граням).
  Каждый примитив объявляет свои группы граней:
  | Примитив | Группы (кол-во граней в группе) |
  |---|---|
  | Cube | `back, right, front, left, top, bottom` (по 2 триангла) |
  | Pyramid | `back, right, front, left, bottom` (по 1) |
  | Plane | `top` (все трианглы) |
  | Sphere | `surface` (все трианглы) |

- **UV-координаты.** Каждая грань получает `faces[i].uv = [u0,v0, u1,v1, u2,v2]`
  (по углу грани, параллельно `indices`), в диапазоне `[0,1]`×`[0,1]`.
  Для куба/пирамиды/плоскости UV строятся по нормали грани (ортогональные оси в
  плоскости грани); для сферы — по параметризации `(theta, phi)`.

- **Перспективно-корректное искажение при ракурсе** — ключевое требование.
  Стандартный механизм: интерполировать `u/w`, `v/w`, `1/w` линейно в экранных
  координатах, затем `u = (u/w)/(1/w)`, `v = (v/w)/(1/w)`. Это даёт «логичное»
  искажение: при повороте грани текстура перспективно сжимается, но узор остаётся
  читаемым. Реализация:
  - `Projection.projectFace` принимает `uvs` (по углу), кладёт `u,v` в каждый
    выходной `pt`.
  - `clipNear`/`lerpVerts` интерполируют `u,v` (линейно в camera-space — корректно).
  - `Rasterizer.fillPoly` считает градиенты `u/w`, `v/w`, `1/w` (по аналогии с уже
    существующим `computeInvWGradient`) и в каждой ячейке восстанавливает `u,v`.

### 1.3 FrameBuffer: per-cell цвет

Текущий `flush` красит прогалины по `meshId` из палитры. Для цветного света и
затемнения текстуры нужен цвет на ячейку:

- Добавить `r/g/b` (например `Float32Array` или `Uint8ClampedArray`, `w*h`).
- `clear()` обнуляет цвет (по умолчанию — материал/палитра или белый).
- Новый `setCellColor(x, y, ch, depth, meshId, r, g, b)` — пишет глиф + цвет;
  существующий `setCell` оставить (цвет = палитра по meshId) ради совместимости
  с тестами.
- `flush()` группирует прогалины по **паре (глиф, цвет)** вместо только id и рисует
  `fillText` с `ctx.fillStyle = rgb(...)`. `meshId`/`ids` сохранить (их проверяют
  тесты), но цвет больше не выводится из палитры.

## 5. Риски и решения

- **Per-cell цвет замедлит flush.** Меньше группировок (по глиф+цвет вместо id) →
  больше `fillText`. Для ascii-разрешения (~тысячи занятых ячеек) допустимо; при
  просадке FPS — группировать по строке/цвету агрессивнее или кэшировать.
- **UV на общих вершинах куба.** Решено: UV на углах граней (`faces[i].uv`), не на
  вершинах.
- **Неоднородный масштаб и нормали.** Мировая нормаль = 3×3 из `worldMatrix`
  (без inverse-transpose). Для ascii-качества приемлемо; при заметных артефактах —
  перейти на `inverse(transpose)` в `Lighting`.
- **Flat-shading даёт ступенчатый градиент.** Это ожидаемо и даже хорошо для ascii.
  Плавный (вершинный) шейдинг — опция позже.
- **«Конус» как spotlight.** В этом плане однонаправленный свет — параллельный.
  Конический falloff (`angle`, `range`) — расширение `Lighting` в этапе B без смены
  интерфейса.
- **Совместимость с тестами.** `FrameBuffer.ids` и `setCell` сохраняем; `flush` меняет
  только цветовую группировку. Старые assert'ы не ломаются.
